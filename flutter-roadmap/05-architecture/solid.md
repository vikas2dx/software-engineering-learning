# SOLID Principles

## Learn
- Single responsibility: group behavior around one reason to change.
- Open/closed: extend behavior without destabilizing existing callers.
- Liskov substitution: implementations preserve the contract callers rely on.
- Interface segregation and dependency inversion for focused boundaries.

## Practice
Take one feature with a large service class and identify a concrete change that is difficult. Refactor only the boundary that makes that change safer.

## Ready when
You can explain the problem a principle addresses and avoid applying it mechanically.
